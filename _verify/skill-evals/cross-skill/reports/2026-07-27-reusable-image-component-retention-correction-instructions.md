# 再利用可能な画像パーツの原則保管 — スキル横断修正指示書

- 作成日: 2026-07-27
- 改訂対象: `requirements-definition` / `basic-design` / `delegate-development`
- 新設対象: `reusable-image-assets`（仮称。システム提供`imagegen`の補助スキル）
- 参照するシステムスキル: `imagegen`（直接変更しない）
- 起点: Big Five Q-012キャラクター制作で、完成画像とは別に猫・時計・カード・首輪を再利用可能なパーツとして保管した実績
- 状態: 修正指示作成済み・各スキルへの実装と配布は未実施

## 追加する原則

ユーザー管理の改訂・新設対象へ、責務に応じた形で次の原則を追加する。
システム提供`imagegen`は変更せず、補助スキルから利用する。

> 高度に生成した再利用可能な画像のパーツは原則保管する。

ここでいう「高度に生成した」は、単純な図形や一時的なサムネイルではなく、次の
いずれかを伴う制作を指す。

- 複数回の生成・編集・差し戻し
- キャラクター、画風、装飾、接触部、解剖、遠近、質感などの一貫性調整
- 合成、部分修正、切り抜き、透過処理、不要物除去
- 人手による品質承認や、再生成コストが高い制作

「再利用可能な画像のパーツ」は、別構図、別画面、演出、共有物、制作参照で再利用
できるキャラクター本体、小物、背景、装飾、テクスチャ、レイヤー、切り抜きなどを
指す。完成画像だけを残し、再利用可能な構成要素を一時生成先や会話履歴だけに残す
状態を避ける。

## 共通の保存契約

プロジェクトで利用する画像を制作し、上記の原則に該当するパーツがある場合は、
完了報告前に次を満たす。

1. 完成画像とは別に、再利用可能なパーツをプロジェクト管理下へ保管する。
2. ラスターの切り抜きは、原則として透過を保持できる可逆・可用な形式
   （通常はPNG）をマスターにする。配信用WebP等は派生物として区別する。
3. 既存マスターを上書きせず、版付きファイル名またはmanifestで版を管理する。
4. パーツの寸法、縦横比、用途、利用上の制約、生成元または承認元をREADMEまたは
   manifestへ記録する。
5. `direct-overlay`、`pose-master`、`style-reference`等、そのまま合成できるか、
   制作参照に留めるべきかを区別する。
6. OSの一時ディレクトリ、会話添付、`$CODEX_HOME/generated_images`だけを保管先に
   しない。
7. 縦横比を維持し、無断のトリミング、引き伸ばし、再配色を行わない。
8. 権利・ライセンス・個人情報・承認状態により再利用範囲が制限される場合は、その
   制約も記録する。

### 例外

次は自動的な保管対象にしない。

- 発想確認だけのプレビュー、明示的な使い捨て案、棄却済みバリエーション
- HTML/CSS/SVG等で確実に再生成できる単純なコードネイティブ要素
- 権利、契約、個人情報、機密性のため保管または再利用してはならない素材
- 分離すると品質・同一性・権利関係を誤認させる素材
- 完成画像へ完全に焼き込まれ、妥当な品質で分離できない要素

プロジェクト成果物であるにもかかわらず保管しない場合は、対象パーツと理由を完了
報告または制作台帳へ残す。「分離が難しい」だけで無言の省略をしない。

## システム提供スキルの改訂方針

`imagegen`のようにCodexまたはプラグインがシステム側で配布・更新するスキルは、
インストール済みコピーを直接上書きしない。今回の原則は次の境界で実装する。

1. システム提供`imagegen`は、画像生成・編集・透過処理・built-in/CLI選択の正典と
   して、そのまま利用する。
2. 再利用パーツの判定、保管、版管理、manifest、完了報告だけを担当する薄い補助
   スキル`reusable-image-assets`（仮称）を、ユーザー管理の正規配布元へ新設する。
3. 補助スキルは`imagegen`の本文を複製せず、
   `**REQUIRED SUB-SKILL:** Use imagegen`のように依存を明示する。
4. `imagegen`のprompt、tool mode、透過処理、CLI/API仕様を補助スキルへ転載しない。
   システム更新へ自動的に追従できるよう、補助スキルは画像資産ライフサイクルの
   追加契約だけを持つ。
5. システム提供スキルと同名の派生コピーを作らない。trigger競合と正典混同を避ける
   ため、別名かつ用途が分かるdescriptionを持たせる。
6. システム提供スキルの更新で補助契約との不整合が生じた場合は、システム側を
   巻き戻したり上書きしたりせず、補助スキルのcandidateを再評価する。

ユーザー管理の正規配布元がある`requirements-definition`、`basic-design`、
`delegate-development`は、各正典をTDDで改訂してから配布先へ同期する。これらを
不要に派生させない。

今回の原則がプロジェクト固有ではなく、システム提供`imagegen`の全利用者へ適用して
も既存契約を壊さないと評価できた場合は、派生スキルの実績を根拠に上流への修正案を
別途作成する。上流で採用・配布されるまでは、ローカルのシステムコピーを先行上書き
しない。

## 対象スキルの洗い出し

### 第1段階で改訂・新設するスキル

| スキル | 対応 | 担当する責務 |
|---|---|---|
| `requirements-definition` | 正典を改訂 | 画像制作がある案件で、再利用対象、保管要否、権利、承認、破棄条件を要件として決める |
| `basic-design` | 正典を改訂 | source master、派生物、ディレクトリ、命名、版、manifest、利用区分、検証方法を設計する |
| `imagegen` | 直接変更しない | 画像生成・編集・透過処理を担うシステム提供の依存先 |
| `reusable-image-assets`（仮称） | 薄い補助スキルを新設 | `imagegen`を利用したproject-bound制作で、再利用パーツを判定・保存・検証・報告する |
| `delegate-development` | 正典を改訂 | 画像制作を委譲するとき、task brief、所有権、完了条件、review packageへパーツ保管契約を含める |

要件定義と基本設計はどちらも対象だが、同じ指示を重複して持たせない。要件定義は
「何を残すべきか」、基本設計は「どこへ、どの形式・版・契約で残すか」を担当する。
画像の生成・編集は`imagegen`、実保存の追加契約は`reusable-image-assets`、委譲時の
受入れは`delegate-development`が担当する。

### 第1段階では直接修正しないスキル

| スキル群 | 判断 |
|---|---|
| `implement` / `prototype` | 原則を重複実装せず、要件・基本設計・`reusable-image-assets`を参照する。画像制作を直接担う評価で欠落が出た場合だけ追加候補とする |
| `writing-skills` / `skill-creator` | スキル作成手順のスキルであり、画像資産ライフサイクルの業務ルールは追加しない |
| `figma` / `canva`系 | ネイティブコンポーネントとラスター画像パーツの契約が異なるため、今回の文言を一律追加しない |
| `presentations` / `pptx` / `documents`系 | パッケージ内画像と外部再利用マスターの境界が異なる。高コストなラスター素材の消失事例が確認された場合に別評価で追加する |

## スキル別の修正指示

### 1. `requirements-definition`

`フェーズ2: Q&Aによる具体化`の開発標準、画像、対象リソースのライフサイクルに、
画像制作を含む案件だけで適用する確認を追加する。

- 高度に生成する画像に、別構図・別画面・演出等で再利用するキャラクター、小物、
  背景、装飾があるか。
- 完成画像だけでよいか、再利用可能なパーツも保管するか。別指定がなければ
  「再利用可能なパーツは原則保管」を標準案として採用する。
- マスター、派生物、棄却案の保持・破棄条件は何か。
- 権利、ライセンス、個人情報、承認状態による利用制約はあるか。

`フェーズ3: ドラフト生成`では、該当案件の要件定義書へ次を反映する。

- 保存対象と保存しない対象
- 原則保管の例外と承認者
- 再利用可能なパーツの受入条件
- 保持期間または削除条件

`後工程（基本設計）への引き渡しチェック`と完了チェックリストへ、該当案件では
再利用パーツの保管要件と例外が決まっていることを追加する。

### 2. `basic-design`

`フェーズ4: 設計判断のQ&A`の既存資産・画面/UX・実装計画へ、要件で保管対象と
なった画像パーツの設計判断を追加する。

- 完成画像、source master、再利用パーツ、配信用派生物の正典
- 保管ディレクトリ、命名、版管理、manifest、provenance
- 透過、縦横比、色空間、解像度等の最小品質
- `direct-overlay` / `pose-master` / `style-reference`等の利用区分
- 承認前、承認済み、棄却済みの状態と公開範囲

`フェーズ5: 設計成果物の生成`では、AI実装指示書と`docs/tasks.md`へ次を追加する。

- 「高度に生成した再利用可能な画像のパーツは原則保管する」を根拠付きの実装規約
  として記録する。
- 画像制作タスクの完了条件に、完成画像、再利用マスター、manifest、検証結果を
  含める。
- 完成画像だけ保存された場合を検出する検証方法を定める。
- 配信用最適化でsource masterを上書きしない。

影響マトリクスには「画像資産の正典・再利用契約を変更した場合」を追加し、
AI実装指示書、資産設計文書、`docs/tasks.md`を同期対象にする。

### 3. `reusable-image-assets`（仮称・新設）

システム提供`imagegen`を直接変更せず、project-bound画像の再利用資産ライフサイクル
だけを追加する補助スキルを新設する。

descriptionは手順の要約ではなく、次のtriggerを判定できる内容にする。

- プロジェクトで利用する生成・編集画像を作る。
- キャラクター、小物、背景、装飾等を別構図・別画面で再利用する可能性がある。
- 生成、編集、差し戻し、切り抜き、合成等の再制作コストが高い。

本文では`**REQUIRED SUB-SKILL:** Use imagegen`を明示し、画像生成・編集そのものは
システム提供`imagegen`へ委ねる。補助スキルが追加する契約は次に限定する。

- 完成画像をworkspaceへ保存するだけでなく、高度に生成した再利用可能なパーツが
  含まれるかを完了前に判定する。
- 該当するパーツは、完成画像とは別の版付きsource assetとしてworkspaceへ保存する。
- 最終合成に焼き込まれたパーツを後から完全に復元できない場合は、可能なら合成前の
  入力またはクリーンな制作参照を保存する。無理な逆分離で品質を捏造しない。
- パーツがそのまま合成可能か、ポーズ/スタイル参照に留まるかを記録する。
- 保存対象がない、または例外に該当する場合は、無言で省略せず理由を報告する。
- 最終報告には完成画像と再利用パーツの保存先を分けて示す。

バッチ生成では、システム提供`imagegen`の「要求された完成画像をすべて保存する」
契約に加え、複数画像間で共通化した高コストなキャラクター、小物、背景、装飾の
source masterも保管対象にする。棄却済みバリエーションをすべて保存する必要はない。

補助スキルへ`imagegen`の全文、prompt taxonomy、built-in/CLI decision tree、
透明化helperの手順をコピーしない。これらは常にシステム提供`imagegen`を正典とする。

### 4. `delegate-development`

`実行手順`の入力品質ゲート、task brief、レビューへ次を追加する。

- 画像制作を委譲する場合、要件・基本設計から、完成画像、再利用パーツ、正典、
  版、利用区分、承認状態、保存先を共有契約表へ抽出する。
- task briefの完了条件へ、原則保管対象のパーツ、manifest、検証方法を明記する。
- 完成画像だけで委譲タスクを完了扱いにしない。
- reviewerはworkspace内の実ファイル、透過・寸法・縦横比・manifest・参照先を
  確認し、担当者の報告だけで保管済みと判断しない。
- 人手のデザイン承認前のパーツを、承認済み正典として登録しない。
- 分離困難、権利制限、使い捨て等の例外は、監督役が根拠を確認して記録する。

## 評価と回帰ケース

スキル本文を先に変更せず、各スキルごとに現行版の失敗を確認してから、1スキルずつ
修正・比較・配布する。

### Case A: 要件定義

入力:

> 20種類のキャラクター画像を生成し、今後別構図でも使いたい。

現行版で、完成画像の形式と縦横比だけを決め、キャラクター本体や小物のsource master
保管、例外、権利、破棄条件を扱わなければbaseline failureとする。

合格条件:

- 再利用対象と保存しない対象を確認する。
- 原則保管を標準案として提示する。
- 受入条件と例外を要件へ残す。

### Case B: 基本設計

入力:

> 要件には、再利用可能なキャラクターと小物を原則保管するとある。

現行版で、完成画像のassets pathだけを設計し、source master、版、manifest、
利用区分、承認状態、検証タスクを設計しなければbaseline failureとする。

合格条件:

- 完成画像と再利用マスターの正典を分離する。
- AI実装指示書と`docs/tasks.md`へ保存・検証契約を反映する。
- 配信用変換でマスターを失わない設計になる。

### Case C: `imagegen`単独と`reusable-image-assets`併用の比較

入力:

> 猫、壁掛け時計、招待状を組み合わせたプロジェクト用画像を作る。猫と小物は後で
> 別構図にも使う。

システム提供`imagegen`単独のbaselineで、最終合成だけをworkspaceへ保存し、
再利用パーツが
`$CODEX_HOME/generated_images`または会話履歴にしか残らなければbaseline failure
とする。

合格条件:

- `imagegen`本体を変更せず、補助スキル併用時だけ追加契約が適用される。
- 完成画像と再利用パーツをworkspaceへ別々に保存する。
- 版と利用区分を記録する。
- 分離不能なら理由と代替マスターを記録する。
- `imagegen`の画像生成・編集・透過処理の既存契約を重複定義しない。

### Case D: `delegate-development`

入力:

> 上記画像制作を担当へ委譲し、完了後にレビューする。

現行版で、task briefとreview packageが完成PNGだけを完了条件にし、再利用パーツの
実ファイルを検証しなければbaseline failureとする。

合格条件:

- task briefに再利用パーツ、manifest、承認状態を含める。
- reviewerが実ファイルとmanifestを確認する。
- 完成画像だけの場合は不合格または根拠付き例外になる。

### 負の回帰ケース

- 「雰囲気を見るだけの使い捨てプレビュー」では、パーツ抽出を必須にしない。
- 単純なSVG/CSS要素では、ラスター画像パーツの保存を強制しない。
- 棄却済みの全バリエーションを無制限に保存しない。
- 未承認パーツを承認済み正典へ昇格しない。
- 権利または機密上保存できない素材を、再利用性だけを理由に保管しない。

## 実装・配布順

1. システム提供`imagegen`単独でbaseline failureを記録する。本体は変更しない。
2. `reusable-image-assets`を新設し、同じケースで実保存の追加契約を評価する。
3. `requirements-definition`を独立評価し、要件の標準案と引き渡しチェックを修正する。
4. `basic-design`を独立評価し、資産構造、manifest、タスク、影響マトリクスを修正する。
5. `delegate-development`を独立評価し、briefとreview gateを修正する。
6. 3つの改訂スキル、1つの新設スキル、依存先`imagegen`を連結したE2Eで、要件から
   制作・委譲・レビューまで契約が欠落しないことを
   確認する。
7. ユーザー管理する4スキルを各正規配布元から配布先へ同期し、hash一致と既存回帰を
   確認する。システム提供`imagegen`のインストール済みコピーは同期・上書きしない。

複数スキルを同時に書き換えてから一括評価しない。どの修正が挙動を変えたかを判定
できるよう、baseline、candidate、回帰結果をスキル単位で残す。

## 今回の実証例

Big Five Q-012では、次をプロジェクト管理下へ保管した。

```text
docs/assets/character-production/components/
  title-pair-conscientiousness-high--extraversion-high/
    cat-base-v1.png
    wall-clock-v1.png
    invitation-card-v1.png
    collar-v1.png
    README.md
    manifest.json
```

この構成では、完成画像を`source-png/`の正典としつつ、再利用パーツを
`direct-overlay`、`pose-master`、`style-reference`へ分類している。スキル修正後も
すべての案件へこの固有ディレクトリ名を強制せず、同じ保存責務と検証可能性を満たす
プロジェクト固有設計を許容する。

## 完了判定

次をすべて満たしたとき、スキル横断の修正完了とする。

- 3つの改訂スキルと1つの新設スキルで、baseline failureとcandidateの改善を確認した。
- 4つのユーザー管理スキルと、依存先`imagegen`の既存評価を回帰させていない。
- プレビュー、コードネイティブ要素、権利制限の負の回帰ケースを通した。
- project-bound画像について、完成画像だけでなく対象パーツの保存先を報告できる。
- 完成画像だけの場合は、保管対象なし、または根拠付き例外として判定できる。
- ユーザー管理スキルの正規配布元と配布先の整合を検証した。
- システム提供`imagegen`を複製・上書き・直接編集していない。
- 補助スキルが`imagegen`の生成手順を重複保有せず、システム更新へ追従できる。
