# Claude アダプター

## 機能を検出する

開始時に、利用可能なサブエージェント起動機能、役割またはモデル選択、共有・分離された作業領域、並列上限、実行権限、プロジェクト指示を確認する。利用可能と確認できた作業担当だけを使う。実行環境に表示されないモデルや機能を前提にしない。

Claude の実行環境は複数あり、サブエージェントの有無が異なる。Claude Code と Cowork ではサブエージェント起動ツール（Agent / Task ツール）が公開され、委譲を実行できる。Claude.ai の通常チャットなど、そのツールが公開されていない環境ではサブエージェントを使えない。環境名で決めつけず、その場のツール一覧に起動ツールが実在するかで判断する。

## 委譲する

監督役として、コンテキストパック、書込み所有権、完了条件、検証、報告契約を渡す。分離作業領域を使う場合は、担当が変更したファイル、差分の取り込み方法、競合時の停止条件を明記する。共有領域を使う場合は、同一ファイルの編集を一人に限定する。

Claude Code または Cowork の Agent（Task）ツールが公開されている場合は、そのスキーマが公開する範囲だけを使う。作業担当の種別は、環境が提示する `subagent_type`（`general-purpose`、`Explore`、`Plan` など）から選ぶ。呼出し単位の `model` 上書きや、対応する場合の `effort` を利用できるか確認する。モデルは、環境変数 `CLAUDE_CODE_SUBAGENT_MODEL`、呼出し単位の指定、エージェント定義の `model`、親会話のモデルという実環境の優先順を尊重する。`haiku`、`sonnet`、`opus` などの別名や完全なモデル ID は、現在の環境で利用可能と確認できた場合だけ指定する。`effort` も、そのモデルが対応すると確認できた値だけを指定する。ツールのスキーマにない種別・モデル名・設定を推測しない。

分離作業領域が必要な場合は、Cowork の Agent ツールが公開する `isolation`（`worktree` など）のように、その環境が提供する分離手段だけを使う。分離手段を使うときは、担当が変更したファイル、差分の取り込み方法、競合時の停止条件をコンテキストパックへ明記する。分離手段が無ければ共有領域とみなし、同一ファイルの編集を一人へ限定する。

通常のサブエージェントは親会話の全履歴を持たないため、会話にしかない制約をコンテキストパックへ明記する。サブエージェントへ別のサブエージェントを起動させず、追加委譲が必要なら監督役へ返させる。

作業担当またはモデル選択を利用できない場合は、利用可能な同一実行主体で実行するか、監督役が単独で実行する。モデル名や使用量を取得できない場合は推測せず、取得可能な指標だけを記録する。Agent（Task）ツールが公開されていない環境（Claude.ai の通常チャット等）では、サブエージェントを前提にせずメイン単独実行へ切り替える。

## 回収して統合する

担当の報告、差分、検証結果を回収し、監督役が統合前に実成果物を確認する。Claude のインストール済みスキルに修正が必要でも、緊急性、締切、権威者の指示、事前承認を理由に直接編集しない。正典を更新・検証してから配布し、配布後に差分を確認する。
