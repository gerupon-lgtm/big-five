# Big Five UI Prototype Notes

## このプロトタイプで判断すること

承認済みの C レイアウトによって、Big Five の体験用サンプルが「根拠が見える」「理解しやすい」「20問から50問へ続けてみたい」と感じられるかを確認します。

## 起動と試用

```powershell
npm.cmd run prototype
```

`http://localhost:4173` を開きます。追加のセットアップやバックエンドは不要です。

## 前提と対象範囲

- これは UI・導線・説明の評価用プロトタイプです。正式な診断、医療的助言、心理評価ではありません。
- 固定の体験用サンプル50問を使います。最初の20問は各因子4問ずつの中間チェックで、残り30問を回答すると50問の詳細結果になります。
- 0〜100 の値はこのサンプル内のスケール値であり、偏差値、能力値、人口に対する順位ではありません。
- 結果、途中回答、履歴はこのブラウザの `localStorage["bigFivePrototype:v1"]` にのみ保存されます。アカウント、API、公開URL、ネットワーク永続化はありません。

## 試用時に確認すること

1. 手動回答を始め、1問回答して戻り、再読み込み後に途中回答を再開する。
2. デモ回答で20問の基本結果を表示し、追加30問後に50問の詳細結果を確認する。
3. 履歴に20問・50問の結果がモードとバージョン情報付きで保存され、同じ条件の結果だけを比較できることを確認する。
4. 20問と50問は比較を拒否し、理由が表示されることを確認する。個別削除と全削除も確認する。
5. 共有プレビュー、画像保存または共有、共有用テキストのコピー、共有できない環境でのテキスト表示を確認する。
6. 幅360pxで横スクロールがなく、キーボードだけでも結果まで到達できることを確認する。
7. 設問画面で、すべての体験用サンプル項目に「体験用サンプル・正式な診断ではありません」と明示されることを確認する。
8. C レイアウトでは、結果タイトル、スコア、結果の理由、注意書きの順で確認でき、タイトルとスコアと理由は最初の表示範囲または直後に到達できることを確認する。
9. 共有用の画像・テキストに生の回答、隠れた個人情報、公開結果 URL が含まれず、共有内容や画像がブラウザ保存されないことを確認する。
10. `npm.cmd test` を実行し、すべてのテストが成功することを確認する。

## 既知のプロトタイプ上の制限

- 項目、採点、タイトル、理由文はすべて固定のサンプルであり、妥当性確認済みの検査ではありません。
- 50問の結果は30ファセットを測定・表示するものではありません。
- Canvasの共有画像はオンデマンド生成です。端末・OS・ブラウザの共有機能によって、画像共有、ダウンロード、テキスト共有の動作は異なります。
- データは同じブラウザ内だけに残り、端末間同期、復元、認証、公開リンク、分析は提供しません。
- このプロトタイプは本番基盤ではありません。個人情報、アクセシビリティの本番監査、セキュリティ運用、実データの検証は未実施です。

## 次の判断パス

試用結果をこのファイルへ記録した後、次の順で正式版の要件と設計を進めます。

1. `requirements-definition` で、対象ユーザー、正式な測定方法、保存方針、公開範囲、評価基準を要件として確定する。
2. `basic-design` で、その要件に基づく画面、データ、認証、運用、セキュリティの基本設計を作成する。

## 将来の VPS 公開メモ

正式版を VPS で公開する場合は、プロトタイプをそのまま公開せず、上記の要件定義と基本設計の完了後に扱います。少なくとも HTTPS・ドメイン、キャッシュとバージョニング、Content Security Policy、利用者同意と問い合わせ先、保存データの方針、結果文言・測定方法の確認、バックアップと運用手順を決めてから公開します。
