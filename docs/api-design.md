# Big Five自己理解支援ツール ベータ匿名集計API設計

| 項目 | 内容 |
|---|---|
| 設計版 | 0.1 |
| 作成日 | 2026-07-20 |
| 入力要件 | `docs/requirements/2026-07-20-big-five-self-understanding-requirements.md` v1.6 |
| 対応機能 | F-017 |
| 対象環境 | ベータ版のみ |

## 1. 目的と境界

ベータテスト中の設問選択傾向、称号判定数、共有カードに実利用された色を、個人単位の履歴を作らず集計する。

- 通常公開版は本APIを呼び出さない。
- APIは既存OCI VPS上で稼働し、既存PostgreSQLへ集計値だけを保存する。
- 氏名、メールアドレス、アカウント、Cookie識別子、端末ID、結果履歴、自由記述を扱わない。
- 個人単位の回答イベント、生回答一式、回答日時を永続化しない。
- Googleフォーム等による感想収集は本APIと分離し、フォーム側で目的と送信内容を明示して別途同意を得る。
- API障害は診断、結果表示、端末履歴、共有カード生成を妨げない。

## 2. エンドポイント一覧

| メソッド | パス | 概要 | 対応機能 |
|---|---|---|---|
| POST | `/api/v1/beta/aggregates/completions` | 完答時の設問選択、称号、完了数を一括加算 | F-017 |
| POST | `/api/v1/beta/aggregates/color-card-actions` | 色付きカードの保存・共有成功時に色利用数を加算 | F-017、F-018 |
| GET | `/api/v1/beta/health` | APIとDB接続の死活確認。集計値は返さない | NF-06 |

集計値を一般公開するGET APIは設けない。

## 3. 共通契約

### 3.1 通信

- HTTPSのみ。
- `Content-Type: application/json`
- Cookie、Authorizationヘッダー、ユーザー認証を使用しない。
- CORSはベータ版GitHub Pagesの確定オリジンだけを許可する。
- `Access-Control-Allow-Credentials`は使用しない。
- リクエスト本文上限は16KBを初期値とする。【想定】
- サーバー受信時刻は集計テーブルの`updated_at`だけに使用し、個別イベント時刻として保存しない。

### 3.2 版情報

すべての加算要求に、集計の比較単位となる版を含める。

- `appVersion`
- `questionSetVersion`
- `scoringVersion`
- `titleRuleVersion`
- 必要な場合は`paletteVersion`

未知の版やマスタに存在しないIDは加算せず、`AGGREGATE_DEFINITION_UNKNOWN`を返す。

### 3.3 二重送信

クライアントは操作ごとに相関しないランダムな`requestId`を生成する。

- 同じ`requestId`の再送は1回として扱う。
- 【想定】サーバーは`requestId`のSHA-256ハッシュだけを冪等キーとして24時間保持する。
- 冪等キーは回答、称号、色、IPアドレスと結合せず、期限後に削除する。
- クライアントは送信成功を端末内へ記録し、通常操作で再送しない。

Q-011で保持期間が確定した場合は24時間の想定値を更新する。

## 4. 完答集計API

### 4.1 リクエスト

```json
{
  "requestId": "5d16d8d2-59d8-4cb7-b17b-67e7d31c7061",
  "appVersion": "beta-0.1.0",
  "questionSetVersion": "ipip-ja-50-v1",
  "scoringVersion": "scoring-v1",
  "titleRuleVersion": "title-rule-v1",
  "questionCount": 50,
  "answers": [
    { "questionId": "Q001", "optionValue": 4 }
  ],
  "titleId": "title-example"
}
```

### 4.2 バリデーション

- `requestId`はUUID。
- `questionCount`は20または50。
- `answers`件数は`questionCount`と一致する。
- 同じ`questionId`を重複させない。
- `optionValue`は1〜5の整数。
- 全設問IDが指定版のマスタに存在する。
- 20問版は固定プレビュー集合、50問版は固定詳細集合と完全一致する。
- `titleId`が指定した判定ルール版・設問数で有効である。
- 余分なフィールドは拒否する。

### 4.3 処理

1. リクエスト全体を検証する。
2. 冪等キーの既処理を確認する。
3. 1トランザクション内で次を行う。
   - 設問×選択肢カウントを回答件数分UPSERTする。
   - 称号カウントを1加算する。
   - 20問または50問の完了カウントを1加算する。
   - 冪等キーハッシュを登録する。
4. コミット後に`204 No Content`を返す。

1件でも不正なら全件をロールバックし、部分加算しない。

## 5. 色付きカード利用集計API

### 5.1 リクエスト

```json
{
  "requestId": "44e1991d-99a5-42be-b33b-fad83a48fe80",
  "appVersion": "beta-0.1.0",
  "paletteVersion": "palette-v1",
  "colorId": "calm-blue",
  "action": "download"
}
```

`action`は`download`または`share`とする。色を選択しただけでは送信しない。画像保存が開始できた時点、またはOS共有が成功完了した時点で送信する。キャンセル・生成失敗・共有失敗は加算しない。

### 5.2 処理

1. 版、色ID、操作種別を検証する。
2. 冪等キーを確認する。
3. 色×操作種別カウントをUPSERTし、冪等キーハッシュを登録する。
4. `204 No Content`を返す。

## 6. レスポンスとエラー

成功時は`204 No Content`。失敗時だけJSONを返す。

```json
{
  "error": {
    "code": "AGGREGATE_PAYLOAD_INVALID",
    "message": "Request could not be accepted."
  }
}
```

| HTTP | コード | 条件 | クライアント動作 |
|---|---|---|---|
| 400 | `AGGREGATE_PAYLOAD_INVALID` | 型、件数、範囲、重複が不正 | 再送せず結果へ戻る |
| 403 | `AGGREGATE_ORIGIN_DENIED` | 許可外オリジン | 再送せず結果へ戻る |
| 409 | `AGGREGATE_DEFINITION_UNKNOWN` | 未知の版・ID | 再送せず版不一致を内部記録 |
| 413 | `AGGREGATE_PAYLOAD_TOO_LARGE` | 本文上限超過 | 再送しない |
| 429 | `AGGREGATE_RATE_LIMITED` | 一時的な送信上限 | 自動再送しない |
| 500 | `AGGREGATE_INTERNAL_ERROR` | DB・処理障害 | 結果を維持。任意の手動再試行だけ許可 |
| 503 | `AGGREGATE_UNAVAILABLE` | 保守・DB停止 | 結果を維持。再送を強制しない |

利用者向けには「匿名集計を送信できませんでした。診断結果には影響しません」と表示し、内部コードを直接表示しない。

## 7. セキュリティ・プライバシー

- API用DBロールは集計マスタ参照、集計UPSERT、冪等キー登録・期限削除だけを許可する。
- SQLはプレースホルダーを使い、動的な列名・テーブル名をリクエストから作らない。
- APIレスポンスへ集計値、DBエラー、SQL、スタックトレースを含めない。
- エンドポイント固有のアクセスログはIPアドレス、User-Agent、Referer、本文を保存しない形式にする。
- アプリケーションログには成功件数、安定エラーコード、処理時間だけを出し、回答値・称号ID・色ID・`requestId`を出さない。
- IPベースのレート制限を行う場合、IPはメモリ上で一時処理し、DB・アクセスログへ永続化しない。
- 集計APIの目的、送信項目、非保存項目、通常版では送信しないことをベータ開始前に表示する。
- DBバックアップにも個人単位イベントを含めない。

## 8. 主要異常系

| 条件 | サーバー動作 | クライアント動作 | 冪等性・競合 | 回復・検証 |
|---|---|---|---|---|
| 二重送信 | 2回目は加算せず204 | 成功として終了 | 冪等キーハッシュ一意制約 | 同一要求2回で1加算 |
| 同時加算 | UPSERTで原子的に加算 | 通常終了 | 複合主キーで競合解決 | 100並列で加算欠落なし |
| 回答1件不正 | 全件ロールバック | 結果を維持 | 冪等キーも登録しない | 部分加算0件 |
| DB停止 | 503、加算なし | 診断結果を維持 | 再送時だけ再試行 | DB停止・復旧テスト |
| 応答消失 | コミット済みなら再送を重複排除 | 任意再試行 | 同じ`requestId` | 1加算のまま |
| 許可外サイト | 403、加算なし | 通常は到達不能 | 非該当 | CORS・直接要求テスト |
| 改ざん版 | 409、加算なし | 再送しない | 非該当 | 未知版テスト |

## 9. 運用

- ヘルスチェックは機密情報や集計値を返さない。
- 冪等キーの期限削除を定期ジョブで実行する。
- 集計テーブルは定期バックアップ対象とする。【要確認】保持期間、バックアップ世代、ベータ終了後の削除・スナップショット方針はQ-011で確定する。
- 集計値の閲覧はVPS・DB管理者に限定する。
- Googleフォーム等の回答とDB集計値を、個人単位で結合しない。
