# ビッグファイブ診断 UIプロトタイプ設計

| 項目 | 内容 |
|------|------|
| 作成日 | 2026-07-20 |
| 状態 | ユーザー承認済み設計・仕様書レビュー待ち |
| 対象 | 体験確認用の静的UIプロトタイプ |
| 本番公開 | 将来VPSへ配置予定 |

## 1. 目的

18歳以上の一般ユーザーが、スマートフォンで一人で利用するビッグファイブ診断の体験を、正式尺度の実装前に確認する。

このプロトタイプで確認する内容は次のとおり。

- 20問回答から基本結果を得るまでの流れ
- 基本結果から追加30問へ進む動機づけ
- 50問完了後の精密結果の情報量
- 信頼性を重視した硬派な結果表現
- 称号、数値、根拠を組み合わせた結果画面
- Canvasによる共有画像のプレビュー
- 端末内の履歴保存と過去結果比較

正式な心理尺度としての妥当性を検証するものではない。設問、スコア、結果はすべて体験確認用サンプルであることを画面上に明示する。

## 2. プロダクト方針

優先順位は次のとおり。

1. 結果への信頼
2. 自分を言い当てられる面白さ
3. 仕事や人間関係への実用性

信頼感とエンタメ性の比率は、おおむね「信頼感7：エンタメ3」とする。

エンタメ性は、判定を誇張するためではなく、称号、グラフ、控えめな結果発表演出、共有体験に加える。

## 3. プロトタイプの位置づけ

本プロトタイプは、捨てることを前提にしたUI・状態遷移の検証用コードとする。

- 正式な診断として公開しない
- サンプル設問とサンプル採点を使用する
- 外部API、バックエンド、ユーザー登録を使用しない
- 実装結果から得た判断だけを本番設計へ移植する
- プロトタイプコードをそのまま本番基盤にしない

正式版では、日本語尺度、採点、結果文章を別途調査・検証したうえで実装する。

## 4. 技術構成

### 4.1 採用方式

静的HTML、CSS、JavaScriptで構成する。

- ブラウザだけで動作
- ビルド工程なし
- 外部ライブラリなし
- 相対パスのみ使用
- Node.jsの簡易静的サーバーを一つのコマンドで起動
- スマートフォンを主対象とし、PCでは中央寄せで表示

### 4.2 採用理由

- 最短で操作可能な体験を作れる
- Canvas、端末保存、共有プレビューを検証できる
- 依存関係が少なく、プロトタイプを削除しやすい
- 将来の本番技術選定へ不要な制約を残さない

### 4.3 想定ファイル構成

```text
prototype-big-five/
├─ index.html
├─ styles.css
├─ app.js
├─ sample-questions.js
├─ sample-scoring.js
├─ sample-results.js
├─ history.js
├─ share-card.js
├─ prototype-server.mjs
└─ NOTES.md
```

各ファイルの責務は次のとおり。

| ファイル | 責務 |
|----------|------|
| `index.html` | 画面領域と基本構造 |
| `styles.css` | モバイル中心の視覚設計 |
| `app.js` | 状態遷移、イベント、画面描画 |
| `sample-questions.js` | 固定50問の体験用設問 |
| `sample-scoring.js` | 20問・50問の体験用採点 |
| `sample-results.js` | 称号、人物像、解説文 |
| `history.js` | 端末内保存、履歴、比較 |
| `share-card.js` | Canvas画像と共有用テキスト生成 |
| `prototype-server.mjs` | ローカル静的配信 |
| `NOTES.md` | 検証する問いと、試用後の判断記録 |

## 5. 設問と採点

### 5.1 プロトタイプ

- 固定50問のサンプル設問を使用する
- 最初の固定20問で基本結果を算出する
- 追加の固定30問完了後に50問版として再計算する
- 各設問は1因子と採点方向を持つ
- 5段階で回答する
- 正方向項目と逆転項目を含め、採点動作を体験できるようにする
- 設問と結果には「体験用サンプル」と表示する

開始画面には「デモ回答を自動入力して体験」を用意する。自動入力による結果には「デモ回答」と表示し、手動回答の履歴と区別する。

### 5.2 正式版への引継ぎ

正式版は、診断バージョンごとに設問を固定する。DBを使用する場合も、設問バンクからランダム抽出しない。

- 20問版は正式な短縮尺度として成立する固定20問
- 50問版は固定20問と固定30問から成る固定50問
- 120問版は30下位側面を測る別の固定尺度
- 50問完了後に70問を足して120問版とする設計は採用しない
- 設問文や採点を変更するときは既存版を上書きせず、新しいバージョンを作る

## 6. 画面と状態遷移

```text
開始
  ├─ 手動で開始
  └─ デモ回答を自動入力
        ↓
1〜20問
        ↓
基本結果
  ├─ 結果を保存して終了
  ├─ 共有プレビュー
  └─ 追加30問へ
        ↓
21〜50問
        ↓
精密結果
  ├─ 共有プレビュー
  ├─ 履歴
  └─ 過去結果との比較
```

### 6.1 開始画面

- プロトタイプの目的
- 正式な診断ではないこと
- 所要時間の目安
- 手動開始
- デモ回答による即時体験
- 履歴がある場合は履歴への導線

### 6.2 回答画面

- 設問文
- 5段階回答
- 現在位置と進捗
- 前の設問へ戻る
- 回答後に次の設問へ進む
- 回答途中の自動保存
- 体験用サンプルの表示

### 6.3 20問の基本結果

承認済みの「C：根拠つきハイブリッド型」を採用する。

表示順は次のとおり。

1. `BIG FIVE 基本結果 / 20問`
2. プロフィール称号
3. 短い人物像
4. 5軸レーダーチャート
5. 特徴的な因子の数値
6. この結果になった理由
7. 5因子すべての尺度内スコア
8. 尺度内スコアであり順位ではないこと
9. 追加30問への案内
10. 共有プレビュー

### 6.4 50問の精密結果

20問版の項目に加え、次を表示する。

- より条件を含む人物像
- 特徴的な2〜3因子の組み合わせ
- 強みが活きる場面
- 強みが裏返りやすい場面
- 自分との付き合い方
- 精密版の共有画像

50問版でも30下位側面を測ったとは表現しない。

### 6.5 共有プレビュー

- 外部へ出る画像を共有前に表示
- 称号
- 20問版または50問版の区分
- 5軸レーダーチャート
- 5因子の数値
- 短い判定文
- サンプル診断の表示

プロトタイプでは、画像ダウンロード、共有用テキストのコピー、OS標準共有の利用可否確認を行う。

公開結果URLは発行しない。

### 6.6 履歴

- 同じ端末の過去結果を新しい順に表示
- 診断日時
- 20問版または50問版
- 手動回答またはデモ回答
- 称号
- 5因子スコア
- 個別削除
- 全削除
- 比較対象の選択

### 6.7 比較

- 原則として同じ設問数、質問セット、採点バージョン同士を比較する
- 20問版と50問版を同じ精度として直接比較しない
- 比較できない場合は理由を表示する
- スコア差を性格の確定的な変化とは表現しない
- 各因子の前回値、今回値、差を表示する

## 7. 視覚設計

- 白から淡いグレーの背景
- 深い緑と濃紺をアクセント
- 日本語の可読性を優先したシステムフォント
- 角丸は控えめ
- 絵文字や過度なゲーム演出を使用しない
- 称号は目立たせるが、心理学上の正式タイプとは表現しない
- 数値と根拠への導線をファーストビューに置く
- レーダーチャートの面積を総合点として扱わない
- 結果発表時のみ控えめなアニメーションを使用する
- 360px前後のスマートフォン幅で横スクロールを発生させない

## 8. スコア表示

5因子は0〜100の尺度内スコアとして表示する。

1〜5の平均回答値を使用する場合の表示変換は次のとおり。

```text
表示スコア = (平均点 - 1) ÷ 4 × 100
```

- 50は日本人平均ではなく、回答尺度上の中央
- 0は特性が存在しないという意味ではない
- 100は能力や人格の完成を意味しない
- 母集団データがない段階では、上位何％などの順位を表示しない

## 9. 端末内データ

### 9.1 保存キー

プロトタイプ専用であることが分かる名前を使用する。

```text
bigFivePrototype:v1
```

### 9.2 保存内容

```text
{
  inProgress: {
    answers,
    currentIndex,
    startedAt,
    mode
  },
  history: [
    {
      id,
      completedAt,
      answerCount,
      mode,
      instrumentId,
      instrumentVersion,
      scoringVersion,
      resultContentVersion,
      scores,
      title
    }
  ]
}
```

`mode`は`manual`または`demo`とする。

### 9.3 保存方針

- 回答途中と履歴を端末内だけに保存
- サーバーへ送信しない
- 履歴の個別削除と全削除を提供
- プロトタイプ終了時に一括削除できる
- 共有画像は永続保存せず、必要時に再生成

## 10. 失敗時の動作

| 状況 | 動作 |
|------|------|
| 端末保存を使用できない | 診断は続行し、履歴を保存できないことを表示 |
| 保存容量不足 | 今回の結果を画面に表示し、保存失敗を通知 |
| 保存データが壊れている | 壊れた部分だけを無視し、利用可能なデータを維持 |
| Canvas生成失敗 | テキスト結果のコピーへ切り替え |
| OS共有が未対応 | 画像保存とテキストコピーを表示 |
| クリップボード未対応 | 手動選択可能なテキストを表示 |
| 再読み込み | 保存済み回答位置から再開 |
| 比較条件が一致しない | 比較不可の理由を表示 |

プロトタイプでは、動作確認に必要な範囲を超える複雑な復旧処理は実装しない。

## 11. アクセシビリティ

- 回答選択肢へ明示的なラベルを付ける
- キーボードで回答できる
- フォーカス位置を視覚表示する
- 色だけで選択状態を伝えない
- 主要テキストは十分なコントラストを確保する
- レーダーチャートの内容をテキストでも表示する
- 共有画像に対応する共有テキストを生成する
- 動きの軽減設定を尊重する

## 12. 確認方法

大規模な自動テストは作成しない。次のスモークチェックを実施する。

### 回答と採点

- 手動で20問を完了できる
- 20問で決まったサンプルスコアが再現される
- 追加30問を完了できる
- 50問で決まったサンプルスコアが再現される
- 逆転項目が正しく処理される
- 戻る操作で回答が壊れない

### 保存と履歴

- 再読み込み後に途中回答を再開できる
- 完了結果が履歴に残る
- デモ回答と手動回答を区別できる
- 履歴を個別削除できる
- 履歴を全削除できる
- 同条件の結果を比較できる
- 異なる条件の結果比較を拒否できる

### 共有

- Canvas画像を生成できる
- 画像に回答内容や不要な個人情報が入らない
- 20問版と50問版を区別できる
- 画像を保存できる
- テキストをコピーできる
- 対応環境でOS共有を起動できる
- 未対応環境で代替手段を表示できる

### 表示

- 360px前後で横スクロールしない
- タップ領域が小さすぎない
- PC幅でも内容が広がりすぎない
- キーボードで主要操作を完了できる
- サンプル診断であることを全主要画面で確認できる

## 13. VPS公開への引継ぎ

正式版はVPSで公開する。

初期の正式版が静的フロントエンドだけで成立する場合は、Nginx等から配信できる。匿名分析、複数診断、管理機能、問い合わせ対応等が必要になった場合にバックエンドとDBを追加する。

本番実装では次を改めて決める。

- フロントエンド技術
- HTTPSとドメイン
- キャッシュとバージョニング
- Content Security Policy
- 匿名分析と同意
- 正式尺度の保存方式
- 結果文章と設問の管理方式
- バックアップと監視

## 14. プロトタイプ完了条件

次の項目をユーザーが一連の操作として体験できれば完了とする。

1. 手動またはデモで回答を開始する
2. 20問の基本結果を見る
3. 追加30問へ進む
4. 50問の精密結果を見る
5. 共有画像をプレビューして保存する
6. 履歴を見る
7. 比較可能な過去結果を比較する
8. 履歴を削除する

## 15. 対象外

- 正式な日本語尺度
- 診断としての妥当性検証
- 本番用バックエンド
- アカウント
- 公開結果URL
- サーバーへの回答保存
- 実際のSNS媒体ごとの完全対応
- 匿名分析の実送信
- 120問版
- 30下位側面
- 相性判定
- 恋愛、適職、採用、臨床に関する断定

## 16. 試用後に残す判断

プロトタイプの試用後、`prototype-big-five/NOTES.md`へ次を記録する。

- 20問回答までの負担感
- 追加30問へ進みたいと感じるか
- C案の結果画面が硬派かつ理解しやすいか
- 共有画像の情報量
- 履歴比較の価値
- 本番へ採用する画面と捨てる画面
- 本番設計で変更する点
