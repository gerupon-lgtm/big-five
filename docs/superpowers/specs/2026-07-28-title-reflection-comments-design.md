# 称号別の振り返りヒント 設計

- 状態: ユーザー承認済み
- 対象版: `mvp-0.1.0`
- 対象機能: F-005、F-006
- 対象タスク: T-005、T-008A
- 対象設計条件: Q-006、Q-014
- 承認日: 2026-07-28

## 1. 目的

測定結果として説明する称号の理由と、利用者が任意に参考にできる実用コメントを分離する。称号と猫を主役にしながら、人格・能力・行動を断定せず、合いそうな提案だけを受け取れる表示にする。

## 2. 決定事項

- 現在の称号別`titleSubtitle`、`titleReason`と因子別結果文の役割・選択構造を維持する。共有資料の「測定結果」は`result-text-v2`の`titleReason`改稿候補にできるが、`result-text-v1`を上書きしない。
- 各称号へ1〜3件の`titleReflection`を固定順で関連付ける。
- 初期表示するのは固定順1件目とし、ランダム選択しない。
- 20問簡易プレビューは1件目だけを表示し、「簡易結果からの参考情報」と明記する。
- 50問詳細結果は1件目を表示し、`ほかのヒントを見る`で残り最大2件を同一階層に展開する。
- 表示見出しは`振り返りのヒント`、補助文は`もし合いそうなら、参考にしてみてください`を基準とする。
- 実用コメントは共有カードと共有テキストへ含めない。
- 因子別の観察文・強み・裏返り・場面別コメントと混在させない。

## 3. 人手編集データ

人手編集正典として、結果文版配下へ`title-reflection-comments.csv`を置く。

| 列 | 型 | 制約 |
|---|---|---|
| text_id | reference | 全結果文内で一意な安定ID |
| result_text_version | version | 対象結果文版と一致 |
| title_id | reference | 51称号のいずれか |
| display_order | integer | 称号ごとに1から連続し、1〜3件 |
| text | text | 非空、前後空白なし |
| status | enum | `draft`／`reviewed`／`approved`／`rejected` |

コンパイラは各行を`section = titleReflection`、`claimKind = reflectionPrompt`の`ResultTextDefinition`へ投影する。1件目だけ`previewAllowed = true`、2〜3件目は`false`とする。runtimeでは配列の固定順を維持し、別のコメントマスタへ再照会しない。

## 4. バージョン

`titleReflection`の追加はsection集合、選択件数、preview／detailの完成契約を変更するため、既存の`result-text-v1`を上書きしない。初回有効化は`result-text-v2`とし、診断定義・VersionTuple・release manifestを同じ版へ更新する。

`result-text-v1`の237件とContent Approval状態は変更しない。`result-text-v2`は、既存237件を承認済み移行元として扱わず、既存文と新規コメントの全gateを版単位で確認する。

## 5. 表現境界

- 測定結果から直接導ける事実として表示しない。
- `あなたは`で人格を固定しない。
- 能力、適職、成果、健康状態、心理状態を断定しない。
- 命令、義務、達成保証、治療・改善効果を含めない。
- 問いかけ、小さな選択肢、任意の行動ヒントとして書く。
- 合わない提案を採用しなくてよいことが表示から分かるようにする。
- 称号理由、因子別詳細、同一称号内の別ヒントと実質重複させない。

2026-07-28に共有された`ipip_comment_proposals_integrated.md`は候補検討資料であり、自動変換・一括採用・承認済み扱いをしない。各文を上記境界、既存237文との重複、根拠・claimKind、Content Approvalで個別審査する。

## 6. 結果生成と履歴

`composeResultTexts`は、20問では該当称号の固定順1件目、50問では該当称号の1〜3件を選択する。表示対象の`RenderedResultText`は他の結果文と同様にResultSnapshotへ複製する。

後にCSVの本文・採否・順序が変わっても、保存済み履歴は診断時のID、版、本文、順序を維持する。過去履歴を現行定義から再生成しない。

## 7. フォールバック

- build時に未知称号、ID重複、0件、4件以上、順序欠損、版不一致、未知列を拒否する。
- approved releaseでは51称号すべてに1〜3件を必須とする。
- 実行時に`titleReflection`だけを表示できない場合も、称号、猫、称号理由、スコア、因子別結果文を維持する。
- 不完全なコメント配列は部分表示せず、振り返りヒント領域だけを省略する。

## 8. 検証

- schema／compiler: 51称号、1〜3件、連続順、参照、版、status、決定的出力。
- domain: 20問は1件、50問は1〜3件、固定順、ランダム入力なし。
- copy lint: 人格固定、能力・効果断定、強制、医療的表現を検出する。
- presentation: 初期1件、追加最大2件、開閉、320px／200%、読み上げ順、キーボード操作。
- snapshot: 診断時本文を保持し、後の定義変更で履歴が変わらない。
- sharing: 共有画像・共有テキストへ`titleReflection`が含まれない。

## 9. 完了条件

- 20問結果では称号理由の後に1件だけ参考ヒントを表示する。
- 50問結果では1件を初期表示し、残り最大2件を明示操作で展開できる。
- 測定結果と任意の提案を見出し・補助文・claimKindで区別できる。
- 共有候補資料を直接移植せず、採用文だけを版付きCSVとContent Approvalへ通す。
