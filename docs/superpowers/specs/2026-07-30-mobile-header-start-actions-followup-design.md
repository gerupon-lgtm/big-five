# モバイルヘッダ・開始操作追補デザイン

- 状態: ユーザー方針承認済み
- 対象版: `mvp-0.1.0`
- 対応タスク: T-008A
- 対応機能: F-001、F-003、F-004
- 基準コミット: `837f10c`

## 1. 目的

実際のGitHub Pagesをスマートフォンで表示した際に、回答画面のヘッダ操作がブランド名へ重なって見える問題を解消する。また、開始画面の説明見出しを本文に合わせ、開始と再開の操作を区別しやすくする。

## 2. 確定変更

### 2.1 回答画面のヘッダ

- 設問回答中と20問完答後の分岐画面だけに付いている`is-sticky`を外し、開始、結果、履歴、比較と同じ通常ヘッダへ統一する。
- `is-sticky`が追加していた固定表示、左右padding、背景、影、角丸、ぼかしは回答画面へ適用しない。
- 中断時に途中回答を保持して開始画面へ戻る既存動作は変更しない。
- 共通ヘッダのブランド寸法は画面別に変えない。開始、回答、結果、履歴、比較で同じ寸法体系を維持する。
- ヘッダ操作は、320px、360px、414pxのすべてで重ならない最初の候補を、次の順で採用する。
  1. `中断してトップへ`
  2. `回答を中断する`
  3. `回答を中断`
- 文言候補の切替前に通常ヘッダへの統一だけで重なりが解消するか確認する。
- いずれの候補でも、横overflowを発生させない。

### 2.2 開始画面の説明見出し

- `Big Fiveについて`を`このツールについて`へ変更する。
- 直下の「20問の簡易プレビューから始め、希望に応じて50問の詳しい結果まで進められます。」は維持する。
- `aria-labelledby`のIDは内容に合う名前へ変更し、見出しとの対応を維持する。

### 2.3 開始・再開ボタン

- `診断を始める`と`途中から再開する`または`残り30問を再開する`を専用の操作グループへ入れる。
- 十分な横幅では同じ横幅の2列とし、ボタン間に12pxの間隔を設ける。
- 狭い画面では同じ横幅の1列へ自動的に切り替える。
- 開始ボタンだけが表示される場合は、操作グループの利用可能幅を使う。
- 開始、再開、確認ダイアログ、進捗置換の既存動作は変更しない。

## 4. テスト

- 通常ヘッダへの統一とボタン配置を期待するテストを先に追加し、失敗を確認する。
- 設問回答中と20問分岐の両方が同じ採用文言を表示し、既存の`onPause`へ委譲することを確認する。
- 開始画面が`このツールについて`を表示し、旧見出しを表示しないことを確認する。
- 操作グループ内の開始・再開ボタンが同じレイアウト規則を使うことを確認する。
- 320px、360px、414pxの実ブラウザでヘッダ重なり、横overflow、ボタン間隔と同幅表示を確認する。
- 全テスト、静的検証、`git diff --check`を通す。
