## Shared contracts

- `continueHidden` returns `detail-continued` and must not call scoring, title classification, result text composition, manifest resolution, snapshot creation, persistence of a result, or result rendering.
- `showPreview` composes `preview20` from exactly 20 answers, saves an answer-free snapshot, and keeps its ProgressRecord for the additional 30 questions.
- `detail-complete` composes `detail50` from exactly 50 answers. Result save success atomically adds the snapshot and removes progress. On result save failure the visible snapshot remains, storage cleanup is best-effort, and the caller drops all in-memory references to the answer map and completed ProgressRecord.
- `characterAssetVersion` is the selected `CharacterManifestEntry.assetVersion`, never `characterManifestVersion`.
- `selectedPaletteId` is the selected TitleProfile's `defaultPaletteId` until Q-013 UI is implemented.
- Result IDs and progress IDs are RFC 4122 UUIDs from an injected provider; times are strict ISO strings from an injected provider.
- The normal build makes no external request.

## Live orchestration state matrix

| Event/state | Storage success | Storage failure or incompatible stored value | Route and in-memory result |
|---|---|---|---|
| New start | Save new progress | Keep new progress only in memory and announce save failure | `#/answer`, question 1 |
| Resume | Load compatible progress | Do not offer resume; do not rewrite the stored value | `#/answer`; a saved `showPreview` decision continues to question 21 |
| Answer/back | Save returned progress | Keep returned progress in memory and announce save failure | Stay on `#/answer` |
| Discard cancelled | No write | No write | Keep current progress and screen |
| Discard confirmed | Delete progress | Keep current in-memory progress and announce deletion failure | Success returns `#/start`; failure stays `#/answer` |
| `continueHidden` | Save detail progress | Keep detail progress in memory and announce save failure | `#/answer`, question 21; no result ID or result model |
| `showPreview` | Save decision, then save answer-free preview snapshot while retaining progress | Keep preview progress and snapshot in memory; announce history-save failure | `#/result?resultId=<id>`; `renderResultRoute` checks the current live snapshot before history |
| Continue after shown preview | Save detail progress | Keep detail progress in memory and announce save failure | `#/answer`, question 21 with `previewDecision: showPreview` |
| `detail-complete` | Save answer-free detail snapshot and atomically remove progress | Keep snapshot in memory, announce history-save failure, accept storage API cleanup result | `#/result?resultId=<id>`; caller clears all answer/progress references in both cases |
| Reload an unsaved live-result URL | No matching history | Do not synthesize or recover answers | Existing missing-result fallback; the prior in-memory result is not persisted |

The live result notice is: `結果は表示できましたが、この端末の履歴には保存できませんでした。` It is visible text and does not replace any title, factor, result text, character fallback, or action.
