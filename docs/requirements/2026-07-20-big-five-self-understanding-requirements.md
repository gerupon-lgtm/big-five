## 2. 背景・目的

### 2.1 背景

一般的な性格診断には「自分を言い当てられた面白さ」がある一方、独自分類や根拠の不明確な文章では結果への信頼を得にくい。そこで、研究蓄積のあるBig Fiveを測定の土台とし、連続的な特性値と根拠を示しながら、称号、グラフ、具体的なコメント、共有体験によって適度なエンタメ性を加える。

### 2.2 目的

18歳以上の一般ユーザーが、スマートフォンで一人で利用し、自分の性格傾向を理解して、仕事、人間関係、ストレス時の自己管理へ役立てられるWebツールを提供する。

本サービスは「心理診断」ではなく「自己理解支援ツール」と表示する。臨床診断、採用判定、能力判定を目的としない。

### 2.3 優先順位

1. 結果への信頼
2. 自分を言い当てられる面白さ
3. 仕事や人間関係への実用性

測定ロジック、出典、限界の説明は硬派に保つ。エンタメ性は測定や採点を変更せず、結果の称号、グラフ、イラスト、結果発表演出、共有体験で強められるものとし、測定上の弱点を隠す表現には用いない。

### 2.4 プロトタイプで確認済みの事項

- 20問相当の回答は短く感じられ、入口として負担が小さい。
- 基本結果の後に追加回答へ進みたいという動機が生まれた。
- 履歴、比較、共有はいずれもMVPから外さない。
- レーダーチャートには外枠、軸、補助線が必要である。
- 根拠文、コメント、結果画面の情報設計は正式版で充実させる必要がある。
- サンプル結果では「当たっている」「根拠に納得できる」という主要価値を評価できていない。IPIP固定設問と正式結果文を用いたベータで再評価する。

## 3. スコープ

### 3.1 MVPの対象

- Big Fiveによる自己理解支援
- IPIP日本語50項目版に基づく固定設問
- 短縮結果から追加回答へ進む二段階体験
- 5因子の尺度内スコア、根拠文、実用コメント
- 最大51種類のプロフィール称号と対応する猫キャラクターの結果表示
- 性格傾向から着想した複数の色候補と、利用場面別の複数の香調候補の表示
- レーダーチャートとテキストによる同等情報
- 回答途中の端末内保存と再開
- 結果履歴、再診断、互換性のある結果同士の比較
- 結果画像・テキストのプレビュー、保存、コピー、OS標準共有
- スマートフォンとPCのWeb利用
- GitHub Pagesによる公開
- ベータ版に限り、OCI VPS・PostgreSQLを用いた設問選択肢、称号、完了数、色付きカード利用の匿名集計

### 3.2 対象外・後続

| 対象外・保留項目 | 理由 | 再検討条件 |
|---|---|---|
| エニアグラム | MVPはBig Fiveの信頼基盤に集中する | Big Five正式版の共通基盤と運用が安定したとき |
| DISC系 | 権利・商標・仕事向け需要の調査が必要 | Big Five公開後に需要と利用条件を確認できたとき |
| 120問版・30下位側面 | MVPには回答負担と設計範囲が大きい | 詳細結果への需要と完答率を確認できたとき |
| アカウント・端末間同期 | 個人情報と運用負担を抑える | 複数端末利用の需要が確認できたとき |
| 公開結果URL | 結果の公開管理と削除責任が増える | アカウント・公開範囲・削除方式を設計したとき |
| LINE・X等の媒体別専用ボタン | OS・ブラウザ・媒体固有仕様への対応が必要 | OS標準共有の実測後、利用媒体の優先度が明確になったとき |
| 通常公開版のアクセス分析 | 正式版では外部送信を行わない | ベータ匿名集計の評価後、収集イベント、通知、保管方針を別途合意したとき |
| 相性の良し悪し、恋愛成否、適職・採用の断定 | Big Fiveから直接断定できず、利用者へ不利益を与え得る | 根拠と安全な表現を別途検証したとき |
| 臨床的助言、能力判定 | 本サービスの目的外 | 再検討しない |

## 4. 用語

| 用語 | 定義 |
|---|---|
| Big Five／五因子モデル | 人格特性を5つの広い次元で捉える心理学上の特性モデル |
| 特性プロファイル | 5因子の連続的なスコアと説明をまとめた本サービスの主結果 |
| プロフィール称号 | 結果を理解しやすくする本アプリ独自の非公式名称。心理学上の正式タイプではない |
| 基本結果 | IPIP 50項目からMini-IPIPの原版選定に対応する20項目を用いて表示する簡易プレビュー。日本語版としての妥当性は未検証 |
| 詳細結果 | 追加30項目を含むIPIP日本語50項目版の完答後に表示する結果 |
| 尺度内スコア | 回答尺度内の位置を0〜100等で表した値。偏差値、能力値、人口順位ではない |
| 互換結果 | 設問数、尺度の識別と改訂版を兼ねる`scaleVersion`、設問版、採点版が一致し、比較可能な結果 |
| 生回答 | 各設問に対して利用者が選択した回答値 |
| 結果スナップショット | 診断時点のスコア、称号、根拠文、コメント、各バージョンを保存したもの |

## 5. As-Is／To-Be

### 5.1 As-Is

- 操作可能な静的プロトタイプがあり、回答、20問・50問相当の結果、履歴、比較、共有の導線を確認できる。
- 設問、採点、称号、文章は体験用サンプルであり、正式な結果への納得感は未検証である。
- 尺度調査により、公開・改変・非商用利用が可能なIPIP日本語50項目版を採用した。日本語版の心理測定上の留保は結果表示へ反映する必要がある。

### 5.2 To-Be

- public domainのIPIP日本語50項目版に準拠し、出典と日本語版の検証上の限界を明示する。
- 利用者が短時間で基本結果へ到達し、希望時だけ詳細結果へ進める。
- 各結果にスコア、根拠、限界、実用的な読み方が表示される。
- 回答と結果を外部へ送信せず、同じブラウザで再開・履歴・比較ができる。
- 個人開発で維持できる静的構成を基本とし、GitHub Pagesから安全に公開できる。

### 8.2 回答・採点

- IPIP日本語50項目版の設問は診断バージョンごとに固定し、設問バンクからランダム抽出しない。
- 20問プレビューには、英語版Mini-IPIPで選定された20項目に対応するIPIP公式掲載の日本語訳を使用する。独自の項目選定や言い換えを行わない。
- 20問プレビューは日本語版Mini-IPIPとして検証済みとは表示しない。
- 20問回答後は結果を表示する前に「簡易プレビューを見る」または「結果を見ずに追加30問へ進む」を選択させる。後者では先入観による追加回答への影響を抑えるため、50問完答まで20問結果・仮称号・仮キャラクターを表示しない。
- 詳細結果は追加30項目を回答した合計50項目から再計算する。
- 回答はIPIP標準に合わせた5件法とし、正方向項目は1〜5、負方向項目は`6 - 回答値`で逆転する。各因子の公式内部得点は該当10項目の平均とする。
- 回答画面の設問本文はスマートフォン20px相当、広い画面22px相当、行間1.5、太字を基準とする。5件法の選択肢は16px相当、行間1.5、最低高56pxを基準とし、文字を縮小して1行へ押し込まない。この尺度は回答画面固有とし、結果・履歴画面へ一律適用しない。
- 0〜100表示は`round((公式内部得点 - 1) / 4 * 100)`とし、比較には丸め前の公式内部得点を使用する。
- 逆転項目、因子割当、欠損値、丸め、表示変換を採点仕様として固定し、IPIP原版の採点鍵と自動テストで照合する。
- 母集団データを正式採用するまで、偏差値、パーセンタイル、上位何％を表示しない。

### 8.3 結果内容

- 主結果は5因子の連続的な特性プロファイルとする。
- 「心理学上のタイプ」と表示しない。
- 称号とキャラクターには「本アプリ独自のプロフィール表現」「心理学上の正式タイプではない」と併記する。
- 結果文は、専門的レビューが可能な固定テンプレートと明示的な条件分岐で生成する。生成AIによる都度生成はMVPで採用しない。
- 高スコアを優秀、低スコアを劣等として扱わない。
- 強みと、同じ傾向が裏返りやすい場面を併記する。
- 「必ず」「向いていない」等の断定を避け、起こりやすい状況と例外を示す。
- 根拠のない精度、妥当性、信頼度の数値を表示しない。
- 基本結果では、5因子、特徴的な2因子、短い人物像、追加回答で確認できる内容を表示し、「20問簡易プレビュー」「日本語版としての妥当性は未検証」と明示する。
- 詳細結果では、各因子、特徴的な組合せ、強み、裏返り、仕事、人間関係、ストレス時の傾向、具体的な行動提案を表示する。ただしIPIP日本語50項目版の検証上の留保を確認できる導線を設ける。
- 因子の主表示は「外向性」「協調性」「勤勉性」「情緒安定性」「知性・想像力」とし、情緒安定性は神経症傾向と逆方向、知性・想像力はBig Fiveの開放性に対応する領域であることを説明する。
- 結果文章の各ルールは、因子定義または採用根拠へ追跡できる対応表を持つ。
- 称号・キャラクターは、2因子の高低組合せ40種類、単一の顕著因子10種類、バランス型1種類の最大51種類とする。
- 20問で簡易プレビューを選んだ場合は「仮称号」「仮キャラクター」とし、50問結果で変わり得ることを表示する。

#### 8.3.1 称号・キャラクター判定ルール

- 本ルールは称号・猫キャラクターを選ぶためのアプリ独自ルールであり、Big Fiveの心理学上の正式なタイプ分類ではない。
- 各因子の丸め前の1〜5内部平均を用い、3.5以上を高傾向、2.5以下を低傾向、2.5より大きく3.5未満を中間とする。0〜100の表示整数は判定に用いない。
- 顕著度は `abs(因子内部平均 - 3.0)` とする。
- 高傾向または低傾向の因子が0個ならバランス型、1個なら当該方向の単一因子型、2個以上なら顕著度上位2因子の高低組合せ型とする。
- 3番目以降の因子は称号選択から除外しても、5因子スコア、根拠文、詳細結果では省略しない。
- 50問版では、因子が高低境界から内部平均0.1以内、または顕著度2位と3位の差が0.1以内の場合を境界・僅差として補足表示する。0〜100換算では2.5点相当である。
- 20問簡易プレビューでは、境界・僅差の範囲を内部平均0.25以内とする。0〜100換算では6.25点相当であり、仮称号が50問版で変わり得ることを表示する。
- 顕著度の順位は丸め前の内部値で比較する。完全同点の場合は、当該方向を支持する回答数、因子内回答の一貫性、固定因子順の順で決定する。
- 当該方向を支持する回答数は、逆転処理後の回答について、高傾向では4以上、低傾向では2以下の項目数とする。回答数も同じ場合は、因子内分散が小さい方を一貫性が高いものとして優先する。
- 最終の固定因子順は、知性・想像力（開放性）、勤勉性（誠実性）、外向性、協調性、情緒安定性（神経症傾向の逆方向）とする。この順序は再現性確保のためだけに使用し、心理学的な優先順位を意味しない。
- 境界・僅差時も称号と猫は1組に確定するが、「複数の傾向が近接し、称号は代表的な2因子を示す」旨を表示する。
- 判定ルールは `title-rule-v1` として独立バージョン管理する。境界等を変更する場合は版を更新し、過去履歴は診断時のルール版で再現する。

#### 8.3.4 結果画面の情報優先度

- 結果発表は本アプリ独自の称号と猫を主役とし、称号、猫、中立副題、非公式表現の注意、`この称号になった理由`をスコア詳細より先に表示する。
- `この称号になった理由`は版付き結果文から取得し、診断時の文面をResultSnapshotへ保持する。因子スコアは診断結果から動的に表示する。
- 称号理由の後に、測定結果と分離した`振り返りのヒント`を置く。`もし合いそうなら、参考にしてみてください`と明記し、人格・能力・行動を断定しない。
- 称号ごとに固定順1〜3件を版付き定義として持つ。20問は1件目だけ、50問は1件目を初期表示して残り最大2件を`ほかのヒントを見る`で同一階層に展開する。ランダム選択しない。
- 振り返りヒントは診断時のResultSnapshotへ保持し、後の文面変更で過去履歴を変えない。共有カードと共有テキストには含めない。
- レーダーチャートは5軸に因子名を表示し、直下に固定因子順で因子名、0〜100の棒、数値、小さな`説明を見る`を配置する。`0–100`は数値列の見出しとする。
- 同時に展開できる因子は1件とする。因子内では「今の傾向」「活かしやすい強み」「強みの裏返り」「仕事」「人間関係」「ストレス」「振り返りと行動ヒント」の固定UIサマリを表示し、`詳しく見る`で診断時の該当結果文を同時に1カテゴリだけ開く。第三階層は設けない。
- `因子ごとの設問構成を見る`では、今回の20問／50問における因子別の正方向項目数と逆方向項目数だけを表示する。設問本文と利用者の回答は表示しない。
- 「測定の土台」「スコアの計算方法」「この結果の限界」「出典・利用条件」は固定説明として、同一画面上のアクセシブルなボトムシートまたは同等の展開UIで確認できるようにする。
- 50問詳細結果には`トップへ戻る`を置く。履歴保存済みなら確認なしで開始画面へ戻り、保存失敗で現在画面にしか結果がない場合は再表示できなくなることを確認してから戻る。

### 8.4 途中回答

- 回答ごとにブラウザ内へ自動保存する。
- 診断種別ごとに1件の進行中データを持つ。将来、Big Five、エニアグラム、DISCを提供する場合はそれぞれ独立して保持する。
- 途中回答に自動有効期限を設けない。
- 利用者が明示的に破棄できる。
- 回答画面では回答数に関係なく`中断してトップへ`を利用でき、保存可能な場合はProgressRecordを保持して開始画面へ戻る。保存できない場合は離脱で回答を失うことを操作前に通知する。
- 再開対象は診断種別ごとの直近1件だけとし、1〜19問と21〜49問は最初の未回答設問、20問完答・選択前は20問分岐、簡易プレビュー表示済みは21問目から再開する。
- 簡易プレビューには`あと30問続ける`、進捗を保持する`中断してトップへ`、20問ResultSnapshotを残してProgressRecordだけを削除する`簡易プレビューで終了する`を用意する。ResultSnapshotの履歴保存を確認できない場合は終了操作を有効化せず、削除失敗時は結果画面に留まって再試行を案内する。
- 互換ProgressRecordがある状態で新規診断を開始する場合は、既存の途中回答を破棄することを確認する。取消時は保持し、確定時だけ同じ診断種別のProgressRecordを置き換える。保存済み結果は削除しない。
- 完答後は当該途中回答を削除する。
- 尺度・設問版が変わった場合は旧回答を混在させず、継続不可理由と再開始を案内する。

### 8.5 履歴・比較

- 生回答は完答後の履歴へ保存しない。
- 結果スナップショットは`resultId`、`completedAt`、`questionCount`、`mode`、9フィールドの`VersionTuple`、5因子、称号ID、キャラクターID・個別アセット版、境界フラグ、診断時の`RenderedResultText`、選択パレットID、カードテンプレート版を保存する。生回答と`diagnosisId`は持たない。
- 結果文章を更新しても、過去履歴は診断当時の文章を表示する。
- アプリ独自の履歴件数上限と自動有効期限を設けない。ブラウザ容量不足時は保存失敗を通知し、画面上の結果は維持する。
- 保存契約では`scaleVersion`（例: `ipip-ja-50-v1`）を尺度の識別と改訂版を兼ねる一意な版IDとして扱う。別の`scaleId`フィールドを要求しない。
- `scaleVersion`、設問版、採点版、設問数、5因子スコアが有効かつ一致する結果だけを比較する。この表現は尺度識別の互換性条件を弱めない。
- 20問相当と詳細版を同じ精度として比較しない。
- 差を性格の確定的変化と表現せず、回答時の状況や自己認識でも変動し得ることを示す。
- 履歴カードの通常表示は、猫サムネイル、称号、実施日時、20問／50問、`結果を見る`へ絞る。スコア全文、結果文全文、内部ID、版情報、削除操作はカードへ常時表示しない。
- `結果を見る`は保存済みResultSnapshotを通常の結果画面で表示し、現行結果文定義から過去文面を再生成しない。
- 比較は履歴画面の固定アクションバーから開始し、カード全体のトグルで最大2件を選ぶ。1件目選択後は互換結果だけを選択可能とし、2件選択後も明示的な比較実行まで自動遷移しない。
- 個別削除、全削除、版情報は履歴ヘッダーの`…`から開く`データの管理`ボトムシート／モーダルへまとめ、個別削除と全削除は確認を必須とする。個別削除を通常カードへ常時表示しない。
- データ管理画面は明示的な`閉じる`、背景部分のタップ、Escキーで閉じられるようにする。内部操作のタップでは閉じず、閉じた後は起動元へフォーカスを戻す。

### 8.10 ベータ匿名集計

- 通常公開版では回答、結果、操作情報を外部へ送信しない。
- ベータ版では利用開始前に、集計目的、送信項目、保存しない項目、送信先、問い合わせ先を読みやすく明示する。集計送信だけを目的とした個別の同意チェックは設けない。
- 個別同意チェックを設けないことを、法令上あらゆる同意が不要という断定には用いない。取得項目、ログ、識別子、第三者提供、利用目的を変更する場合は、通知・同意・プライバシー説明を再評価する。
- 回答完了時に、設問セット版、採点版、設問数、設問IDと選択肢、判定ルール版、称号IDを一括送信する。サーバーは検証後、設問×選択肢、称号、20問／50問完了の集計値だけを同一トランザクションで加算し、個人単位の回答イベントを保存しない。

- 氏名、メールアドレス、アカウント、Cookie識別子、端末ID、自由記述、結果履歴を送信・保存しない。IPアドレス、User-Agent、Referer、リクエスト本文を永続ログへ残さない。
- 通信失敗、拒否、タイムアウト、集計API停止でも診断結果、履歴、共有を維持し、自動再送を強制しない。

- 色候補の選択は任意とし、選ばなくても標準配色で結果閲覧、履歴、共有へ進める。
- 色候補を選ぶと、共有カードの背景、装飾、グラフ等の配色プレビューを更新する。選択は診断スコア、称号、猫キャラクター、結果文を変更しない。
- 選択色と猫キャラクターが同系色になる組合せを許容し、その理由だけで候補色を除外、差し替え、または猫を再配色しない。
- カード描画時は猫の輪郭と隣接背景の視認性を確認し、必要に応じて明暗二重の縁取り、影、ニュートラルな背景プレートのいずれかまたは組合せを適用する。
- 視認性補助は共有前プレビューと保存・共有される完成画像で一致させる。猫の縦横比、全体表示、称号との対応は変更しない。
- 香調候補は香りのイメージと雰囲気の提案に限定し、具体的な商品、精油の用量・滴数・DIY配合、摂取、皮膚塗布、ディフューザー等の使用方法を案内しない。
- 各香調候補には、植物名・精油名を区別しない「香りの素材例」を1〜3件表示できる。素材例は香りのイメージ補助に限定し、精油・商品・使用を勧める表現にしない。
- 香り素材は版付きの独立マスタとし、称号別selectorが`fragranceId`、香調候補が固定順の`materialId`を参照する。名称を称号別データや関連表へ重複保持しない。
- 色は個々のHEXを独立マスタ化せず、主・副・差の3色を持つ版付きパレット単位で管理し、称号から標準1件と代替2件の`paletteId`を参照する。
- 香りの素材例は通常結果画面だけに表示し、共有カードと共有テキストには含めない。
- 動物飼育、健康状態等の追加質問は設けず、香料への敏感さ、妊娠・授乳、乳幼児、ペット等への一般的な注意書きを共通表示する。
- 「治療する」「改善する」「集中力を上げる」等の効果断定を禁止し、「象徴色」「香調候補」「雰囲気づくりのヒント」等の表現を用いる。

## 10. データ要件

### 10.1 保存場所

- 途中回答と履歴はブラウザ内ストレージだけに保存する。
- 通常公開MVPではサーバーDBを使用しない。
- ベータ匿名集計だけは稼働中のOCI VPS上の既存PostgreSQLを使用し、ブラウザの端末履歴とは分離する。
- ブラウザデータ削除、端末変更、プライベートブラウズ等により復元できないことを事前に説明する。

| 診断定義 | 診断ID、尺度ID・版、設問版、採点版、結果文版、称号判定ルール版、固定設問 | アプリ配布物 |

- 実施日時はISO 8601形式で保存し、画面では利用者のローカルタイムで表示する。
- 利用者が日付・時刻を入力する画面はMVPにないため、日付ピッカー・キー入力標準は非該当とする。

## 11. 外部連携

- 通常公開MVPは外部API、認証、分析、サーバー保存を使用しない。
- ブラウザ標準のWeb Share、Clipboard、Canvas、Download機能を利用する。
- ベータ版だけはOCI VPS上の匿名集計APIへ接続し、既存PostgreSQLの専用集計テーブルを更新する。APIキー、Cookie、アカウント認証は使用しない。
- ベータアンケートはGoogleフォーム等のアプリ外手段へ分離し、フォーム側で別途同意を得る。生回答や診断結果の提出を必須にせず、匿名集計値と個人単位で結合しない。

## 12. 稼働環境

- MVP、ベータ、正式版のフロントエンドをGitHub Pagesで公開する。
- ベータ匿名集計APIは稼働中のOCI VPS、集計DBは同VPSから接続できる既存PostgreSQLを使用する。通常公開版はこのAPIへ接続しない。
- アプリはビルドなしでも配信可能な静的HTML・CSS・JavaScriptを基本とする。
- GitHub Actionsから静的成果物をPagesへデプロイする方式を基本とし、公開元フォルダとワークフローの詳細は基本設計で決定する。
- 公開前の専用検証環境は設けない。ローカルサーバー、対象ブラウザのスモークテスト、Pull Request上の自動テストで検証する。
- デフォルトブランチへ反映された承認済み変更だけを公開対象とする。
- GitHub Pagesの「Enforce HTTPS」を有効にし、HTTP参照を含む混在コンテンツを禁止する。
- Pagesサイトはインターネットへ公開されるため、リポジトリと公開成果物に秘密情報・生回答・診断結果を含めない。
- 初期公開URLは`github.io`ドメインを利用できる。カスタムドメインは後続の任意設定とする。

## 13. 移行要件

- UIプロトタイプのコードをそのまま本番基盤として扱わない。
- プロトタイプから移植するのは、検証済みの画面構成、状態遷移、エラー処理、テスト観点とする。
- プロトタイプのサンプル設問、採点、称号、結果文、保存データを正式版へ移行しない。
- 既存利用者データは存在しないため、データ移行は不要である。

## 14. 運用・保守要件

- 個人開発者がGitHubリポジトリ、Pages、Actions、監視、リリース、問い合わせを管理する。
- 外形監視を設定する。
- 自動テスト成功後にだけデプロイし、重大障害時は安全なGitコミットを再デプロイして切り戻す。
- 回答・結果をURL、リポジトリ、配布物、Actionsログへ記録しない。
- URLのクエリ・フラグメントに生回答、診断結果、個人情報を含めない。
- 問い合わせ先と利用上の注意を公開ページから確認可能にする。
- 障害対応時間の保証は行わないが、重大な採点・プライバシー不具合は公開停止または切り戻しを優先する。

## 17. 成功基準・受入基準

### 17.1 MVP受入基準

- IPIPのpublic domain条件、50項目、20項目選定、採点根拠、日本語版の限界を確認できる。
- 固定設問、逆転、採点、丸めを自動テストで再現できる。
- 20問後に結果を見ず50問へ継続でき、または20問簡易プレビューを完了できる。
- 20問では仮称号・仮キャラクター、50問では詳細称号・キャラクターを表示できる。
- 回答途中から再開でき、設問版不一致時には安全に再開始できる。
- 回答中に明示的にトップへ中断でき、20問選択前、簡易プレビュー後、21〜49問の各状態を正しい位置から再開できる。
- 簡易プレビューで終了した場合は20問結果を履歴に残し、追加30問用の途中回答だけを削除できる。
- 途中回答がある新規開始は確認取消で既存進捗を保持し、確定時だけ置き換える。
- 履歴で診断当時の根拠文・コメントを確認できる。
- 結果では称号と猫を主役として理由を先に示し、5因子を名前付きレーダー、棒、数値、段階説明で確認できる。
- 20問では称号別の振り返りヒント1件、50問では初期1件と展開可能な追加最大2件を、測定結果ではない任意の参考情報として確認できる。
- 保存済み50問結果から直接トップへ戻れ、未保存結果を失う場合だけ離脱確認が出る。
- 履歴のデータ管理画面を閉じるボタン、背景タップ、Escキーで閉じ、起動元へフォーカスを戻せる。
- 履歴の固定比較導線から互換2件をトグル選択でき、明示操作で比較へ進める。
- 互換結果だけを比較できる。
- 共有前プレビュー、画像保存、テキストコピー、OS標準共有と代替動作を確認できる。
- 色・香りの追加質問なしで結果を閲覧でき、複数候補が非診断的な提案として表示される。
- 色を任意選択すると共有カードの配色が変わり、その画像を保存・共有できる。未選択時も標準配色で同じ操作を完了できる。
- 猫と背景が同色・近似色になる代表ケースでも、利用者が選んだパレットを維持したまま輪郭を識別でき、共有前プレビューと完成PNGが一致する。
- 生回答が完答履歴、共有物、サーバーへ残らない。
- 360px幅と対象ブラウザで主要操作を完了できる。
- 最大51種類の全判定が有効な称号ID・キャラクターIDへ対応し、欠落・重複・未参照アセットがない。
- `title-rule-v1`の高・中・低境界、0・1・2因子以上の分類、3因子以上、境界・僅差、完全同点、20問・50問の各代表ケースを自動テストで再現できる。
- 同一回答と同一判定ルール版からは常に同一の称号ID・キャラクターID・境界表示が得られる。
- キャラクター読込失敗時も称号、スコア、結果文、共有テキストを利用できる。
- 重大な採点、保存、共有、キャラクター対応、プライバシー不具合が0件である。

### 17.2 ベータ成功指標

- 対象者10〜30人程度で限定テストを行う。
- テスターの80%以上が結果を理解できる。
- テスターの70%以上が「自分の傾向を捉えている」と回答する。
- 20問プレビューの負担感、50問詳細への継続意向、限界説明の理解、結果の根拠理解、共有・履歴・比較の利用感を個別に確認する。
- 「当たっている」と「根拠に納得できる」を別の質問として評価する。
- ベータ評価は使いやすさと納得感の確認であり、尺度の心理測定上の妥当性検証の代用とはしない。

### 17.3 正式公開条件

- MVP受入基準を満たす。
- ベータの理解度・傾向把握指標を満たすか、未達理由と改善判断を記録する。
- 結果文と注意書きが採用根拠の範囲を超えていない。
- 主要スマートフォン環境で一連の操作を完了できる。
- GitHub PagesのHTTPS強制、主要ブラウザでの公開確認、外形監視、Gitコミット単位の切り戻し、問い合わせ先を準備する。
- 尺度名、出典、利用条件、自己理解支援ツールであることを表示する。
